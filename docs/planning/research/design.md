# FunZone: дизайн-аудит и дизайн-направление

Автор: Jony (продуктовый дизайнер), совет по планированию.
Ревизия 2, 2026-10-06. Учтены вводные владельца:
- первая языковая пара **RU↔HE**, иврит и RTL с первого дня, затем RU↔EN;
- цель — full-stack портфолио;
- UI игр и общие компоненты **переписываются с нуля**, старый вид сохранять не нужно;
- вместо 35 игр — **6–8 игр по математике и логике**, контент хранится в данных.

Статус: только планирование, продуктовый код не менялся.

## 0. Коротко

1. **Текущий UI служит уроком, а не основой.** Аудит (раздел 1) я сохранил: каждая находка стала требованием к новой системе (сводка в 1.9). Сам вид ABCya-клона не переносим.
2. **RU↔HE с первого дня меняет приоритеты.**
   - RTL — базовое состояние, а не «поддержка».
   - Шрифт должен покрывать кириллицу и иврит **с огласовками (никуд)**. Я проверил: Rubik это умеет, Nunito иврит не поддерживает вообще.
   - Голоса `he-IL` для браузерного TTS есть не везде, поэтому **заранее записанное аудио входит в MVP**, а не откладывается «на потом». При 6–8 играх с контентом в данных это реально: фраз мало, и они конечны.
3. **Визуальное направление нужно новое.** В разделе 3.0 три варианта. Рекомендую **«Игрушечную геометрию»**: фигуры одновременно служат и декором, и учебным контентом (круг, квадрат, счёт, паттерны). Они культурно нейтральны и одинаково работают в LTR и RTL.
4. **6–8 игр не надо собирать из 35 компонентов.** Их лучше построить как **4 шаблона механик**, которые питаются данными (раздел 3.4). Тогда дизайн-система — это движок раунда плюс шаблоны, и новая игра — это JSON, а не JSX.
5. **Порядок работ под full-stack портфолио.** Сначала фундамент с RTL, потом раунд со звёздами, потом шаблоны и игры, потом гость и онбординг языков, потом аудио, лендинг и case study. Родительская зона с профилями поднята выше карты прогресса: это лучшая витрина full-stack (аутентификация, модель данных, приватность).

## 2. Ключевые флоу нового направления

### Модель языков

- **L1** — родной язык ребёнка, язык оболочки и подсказок. **L2** — целевой язык, язык заданий.
- `dir` оболочки задаёт L1, `dir` карточки задания задаёт L2.
- Пара RU↔HE двунаправленная:
  - **RU→HE**: русскоязычный ребёнок учит иврит. Оболочка LTR, задание RTL.
  - **HE→RU**: ивритоязычный ребёнок учит русский. Оболочка RTL, задание LTR.
- Именно поэтому RTL нельзя «добавить потом»: в обоих направлениях на одном экране одновременно живут оба направления письма.
- EN подключается позже как третий язык той же модели. В выборе языка он виден как неактивная плитка «скоро».

**Никуд.** Иврит как L2 и иврит для детей 4–6 лет нужно показывать **с огласовками**: без них ученик не прочитает слово. Для L1 = HE у детей 8+ огласовки можно выключать в настройках родителя. В данных храним обе формы (`he` и `he_nikud`), а не генерируем их, потому что автоматическая расстановка ненадёжна.

### 2.1 Гость: «Играть сейчас» без логина

1. `/` — лендинг. Для ребёнка огромная кнопка «▶», для взрослого — блок ниже.
2. Первый запуск: выбор языков (2.2), 2 тапа, всё озвучено.
3. Выбор возраста: 3 плитки-картинки «4–5 / 6–7 / 8–10». Можно пропустить, по умолчанию 6–7.
4. Карта или хаб с 6–8 играми, первая игра подсвечена.
5. Раунд (2.3), затем экран звёзд.
6. После 1-го раунда появляется плашка **для взрослого**: «Сохранить прогресс → для родителей». Прогресс гостя лежит в `localStorage` и переносится в профиль после регистрации. Это и есть мост к full-stack части.

### 2.2 Выбор языков, переключатель, аудио

**Первый запуск:**
1. «На каком языке ты говоришь?» Плитки с самоназванием языка: «Русский», «עברית», «English (скоро)». Флагов нет: флаг обозначает страну, а не язык. Язык браузера предвыбран. Тап по плитке произносит её название.
2. «Какой язык учим?» Выбранный L1 неактивен. При L1 = RU предвыбран HE, и наоборот.
3. Персонаж говорит «Привет! !שלום», и ребёнок переходит на карту.

```
Первый запуск, шаг 2 (L1 = HE → оболочка RTL)
┌──────────────────────────────────────────┐
│                    ?איזו שפה נלמד  🔊    │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐  │
│  │   Aa     │ │   אא     │ │   Аа     │  │
│  │ English  │ │  עברית   │ │ Русский  │  │
│  │ (скоро)  │ │ (родной) │ │   🔊     │  │
│  └──────────┘ └──────────┘ └──────────┘  │
│   ░ неактивно ░  ░ неактивно ░   ← выбор │
└──────────────────────────────────────────┘
```

**Переключатель внутри игры** работает как «подглядывание», а не как смена режима:
- Задание показано и озвучено на L2. Кнопка `[⇄]` (`aria-pressed`) показывает перевод на L1 под заданием и проговаривает его.
- Звёзды за перевод не снимаются. Родителю в статистике видно «решено с переводом»: это слово стоит повторить.
- Каждый раунд снова начинается с L2.
- Числа в заданиях всегда пишутся цифрами и озвучиваются на L2. Это главная языковая польза математики: «שבע» / «семь».

**Аудио в MVP:**
- Фразы и числа берутся из данных и **заранее записываются** (или генерируются один раз и хранятся как файлы): числа 0–20 (позже 0–100), около 20 инструкций, около 10 похвал, около 30 слов (цвета, фигуры, «больше/меньше»). На каждый язык выходит примерно 80–150 коротких файлов.
- Браузерный `speechSynthesis` остаётся только запасным вариантом. Когда нет ни файла, ни голоса, кнопка 🔊 показывается в состоянии `unavailable`, а игра остаётся проходимой.
- Голос нужен один на язык и стабильный: для ребёнка смена голоса — это смена персонажа.

### 2.3 Структура раунда

**Старт → N вопросов → экран со звёздами.** N = 5 для возраста 4–5 и N = 8 для 6+, задаётся в данных игры.

1. **Интро** (около 3 с, пропускается тапом): пиктограмма игры, озвученная инструкция на L2, кнопка «▶».
2. **Вопрос:** QuestionCard, кнопки 🔊 и ⇄, варианты ответа, RoundProgress из N сегментов. Сегменты заполняются по направлению L1.
3. **Ответ:**
   - **верно:** галочка, кнопка «подпрыгивает», звук, похвала на L2 с озвучкой. Автопереход через 1.2 с (одно значение для всех игр) или раньше, по тапу «→».
   - **неверно:** мягкое покачивание, янтарный цвет «попробуй ещё» вместо красного, неверный вариант гаснет. После 2-й ошибки верный вариант подсвечивается, и ребёнок нажимает его сам.
4. **Экран конца:** звёзды, «7 из 8», стикер. Кнопки «Ещё раз», «Дальше» и «Карта».
5. **Выход посреди раунда:** «✔ / ✖» картинками.

**Правило звёзд:**
- ★ — раунд пройден, выдаётся всегда.
- ★★ — не меньше 60% вопросов решено с первой попытки.
- ★★★ — не меньше 90%.
- Сохраняется лучший результат.

### 2.4 Карта прогресса и награды

- При 6–8 играх карта — это **одна тропинка** из 6–8 узлов, а не три. Порядок задаётся по возрасту и сложности. На каждом узле видны пиктограмма и 0–3 звезды.
- Карта рекомендует, но ничего не запирает: все игры доступны всегда.
- Альбом стикеров-фигур (1 стикер за каждые 5 звёзд) — это только коллекция. Валюты, магазина и серий дней нет, сравнения с другими детьми тоже.
- В RTL тропинка идёт справа налево, а цифры на узлах не зеркалятся.

### 2.5 Родительская зона: гейт, профили, без email ребёнка

### 3.0 Визуальное направление: три варианта

| | A. «Игрушечная геометрия» | B. «Тетрадь в клетку» | C. «Ночное небо» |
|---|---|---|---|
| Суть | Плоские яркие фигуры (●▲■◆), толстые скругления, «деревянные игрушки». Персонаж собран из фигур. | Тёплая бумага, сетка-клетка, линии «от руки», цифры как герои. | Тёмный фон, звёзды-награды, светящиеся элементы. |
| Плюсы | Фигуры — это **сам учебный контент** (счёт, сравнение, паттерны), поэтому декор работает на обучение. Культурно нейтрально, без букв и символов. Дёшево: CSS и SVG без иллюстратора. Одинаково работает в LTR и RTL. | Спокойно, «по-школьному», узнаваемо и в RU, и в IL. Хорошо для 8–10 лет. | Эффектно на скриншотах. Звёзды как естественная метафора наград. |
| Минусы | Риск выглядеть как «ещё одно детское приложение», если не держать строгую сетку и палитру. | Для 4–5 лет скучновато, линии «от руки» трудно сделать без иллюстратора. | Тёмный фон днём и для малышей — плохой выбор. Двойная работа по контрасту, конфликтует с отказом от тёмной темы. |
| «Вау» в портфолио | Высокое: живые фигуры в моушене и система, которую видно. | Среднее. | Высокое на скриншоте, низкое в использовании. |

**Рекомендация: A.** Основание: одна визуальная система одновременно служит брендом, декором и учебным материалом. Это редкая и хорошо объяснимая в case study идея («фигуры — это и бренд, и контент»). От B можно взять тонкую сетку-клетку как фон карточки задания: она помогает выравнивать объекты для счёта.

### 3.1 Токены (новые, не наследуют ABCya-оранжевый)

Принципы:
- Яркий цвет — это **fill**: фигуры, декор, крупные плоскости. Текст на fill всегда тёмный (`--ink`).
- Для кнопок с белым текстом есть **strong**-вариант с контрастом не ниже 4.5:1.
- Состояние «попробуй ещё» — **янтарное**, не красное: это не наказание.
- Контраст ниже посчитан на `--paper` и на белом.

### 3.2 Шрифты (проверено по файлам шрифтов)

Покрытие взято из `METADATA.pb` в google/fonts. Огласовки проверены по cmap и наличию GPOS-фичи `mark` в TTF-файлах.

| Шрифт | Latin | Cyrillic | Hebrew | Никуд (U+05B0–05C7) | Variable |
|---|---|---|---|---|---|
| Nunito (сейчас) | ✔ | ✔ | **✘** | ✘ | wght 200–1000 |
| **Rubik** | ✔ | ✔ | ✔ | **17/24** + `mark` | wght 300–900 |
| Fredoka | ✔ | **✘** | ✔ | 18/24 | wght, wdth |
| Varela Round | ✔ | **✘** | ✔ | 17/24 | — |

У Rubik нет только meteg, rafe и пунктуации (paseq, sof pasuq, nun hafukha, upper/lower dot). Это библейские и кантилляционные знаки. **Все гласные современного детского никуда есть**, включая дагеш, точки шин/син и холам.

**Решение: Rubik — единственная гарнитура.**
- **Self-host**, без Google CDN: это детский продукт, и запросы к третьим сторонам не нужны.
- Woff2 разбивается по `unicode-range` на latin, cyrillic и hebrew. Русскоязычный ребёнок не качает иврит, но иврит всё равно нужен на экране как L2, так что в паре RU↔HE обычно грузятся оба подмножества. Тем важнее брать только нужные начертания: одна variable-ось вместо 5 файлов.
- Для никуда задаётся `line-height: var(--leading-he-nikud)` на `[lang="he"]`. Перед утверждением нужна проверка на реальных словах **носителем** при 18px и при 60px.
- Цифры: `font-variant-numeric: tabular-nums` для счёта и прогресса.

### 3.4 Игры как данные: 4 шаблона механик

Предложение дизайна. Окончательный набор игр определяет стратег.

| Шаблон | Механика | Игры (кандидаты) | Языковая польза (CLIL) |
|---|---|---|---|
| **choose** | задание + 2–4 варианта | Сколько? (счёт), Сложение до 10/20, Какая фигура?, Какой цвет? | числа, фигуры, цвета на L2 |
| **compare** | два набора, выбор больше/меньше/равно | Больше или меньше | «больше / меньше / столько же» — **отношения**, не только существительные |
| **sequence** | ряд с пропуском | Что дальше? (узоры из фигур и чисел) | «следующий», порядковые числительные |
| **pairs** | memory: слово ↔ картинка, число ↔ количество | Найди пару | связь слово–образ на L2 |

Пример данных одной игры:

```json
{
  "id": "count-shapes",
  "template": "choose",
  "category": "math",
  "ageBand": "4-5",
  "roundLength": { "4-5": 5, "6+": 8 },
  "prompt": "prompt.howMany",
  "generator": { "type": "count", "min": 1, "max": 10, "shapes": ["circle", "square"] }
}
```

Тексты берутся из словаря по ключу (`prompt.howMany` → `ru` / `he` / `he_nikud`), аудио — по тому же ключу.

TellTime и лабиринт в MVP не берём. Часы нельзя зеркалить, а лабиринт сложно сделать доступным и адаптивным. Это хорошие кандидаты для второй волны.

### 3.5 Стратегия RTL

- `<html lang dir>` берётся из L1. Карточка задания и перевод получают свои `lang`/`dir`.
- Только логические свойства (`margin-inline-*`, `padding-inline`, `inset-inline-*`, `text-align: start`). Это закрепляется линтером: stylelint с плагином для logical properties, решение за architect.
- **Зеркалятся:** раскладка, RoundProgress, стрелки «назад/дальше», тропинка на карте, анимация перехода между вопросами, положение [✕] и [🔊].
- **Не зеркалятся:** цифры и выражения (`<bdi dir="ltr">3 + 4</bdi>`; в иврите арифметика тоже пишется слева направо), последовательности в шаблоне `sequence` (числовой ряд всегда LTR; ряд фигур идёт по направлению L2, это решено и задокументировано), фигуры, логотип, кнопка проигрывания.
- Иконки-стрелки — SVG с `.flip-rtl`, без символов ◄ ►.
- Смешанные строки оборачиваются в `<bdi>`.
- Тестовые пары: RU→HE и HE→RU на каждом экране. Самый длинный язык для кнопок обычно русский.

### 3.6 Тёмная тема: не делать

Аудитория — дети 4–10, они играют днём. Тёмная тема удваивает работу по контрасту, а пользы почти не даёт. Вместо неё **«спокойный режим»**: без конфетти и параллакса, с тихими звуками. Он включается автоматически при `prefers-reduced-motion` или вручную в настройках родителя.

## 4. Пакеты дизайн-работ по «вау на час»

Сложность 1–4 (1 — вечер, 4 — несколько недель при 5–10 ч в неделю). Часы ориентировочные. Всё пишется с нуля.

### P1. Фундамент: токены, Rubik, RTL-оболочка — сложность 2, около 8–10 ч
- **Scope:** токены 3.1; self-host Rubik с `unicode-range`; AppShell с `LocaleProvider` и `lang`/`dir`; глобальные `:focus-visible`, reduced motion, `touch-action`; SVG-набор фигур `Shape`; страница-«витрина токенов» (пригодится для case study).
- **Файлы:** новые `FE/src/styles/tokens.css`, `FE/src/styles/base.css`, `FE/public/fonts/*`, `FE/src/components/app/AppShell*`, `FE/src/components/ui/Shape*`. Старые `colors.css` и `App.css` заменяются.
- **DoD:** экран-витрина корректно рендерится в RU (LTR) и HE (RTL с никудом); 0 нарушений контраста в axe; нет запросов к fonts.googleapis.com; при `reduce` нет анимаций.

### P2. Движок раунда и экран звёзд — сложность 3, около 12–16 ч ★ максимум «вау»
- **Scope:** GameShell и `useRound`, QuestionCard, AnswerGrid, Feedback, RoundProgress, EndScreen; лестница подсказок; правило звёзд; game mode; motion (нажатие 120 мс, «подпрыгивание» на верный ответ, мягкое покачивание на неверный, звёзды влетают по одной, лёгкое конфетти из фигур бренда на CSS/SVG без библиотек). Проверяется на первом шаблоне `choose`.
- **Файлы:** новые `FE/src/components/game/*`, `FE/src/components/game/templates/Choose*`.
- **DoD:** одна игра проходится от интро до звёзд на 360px и на 768×1024 в обеих ориентациях, в RU→HE и HE→RU; ответы ≥ 64/80px; обратная связь объявляется скринридером; тесты qa на `useRound` и правило звёзд зелёные.

### P3. Шаблоны и 6–8 игр в данных — сложность 3, около 12–18 ч
- **Scope:** шаблоны `compare`, `sequence`, `pairs`; CountField и NumberPad; словари RU/HE/HE-nikud для всех игр; честное перемешивание.
- **Файлы:** `FE/src/components/game/templates/*`, данные игр и словари (структура за architect).
- **DoD:** все игры проходятся в обеих парах; 0 захардкоженных строк в JSX игр; новая игра добавляется только данными. **Тексты на иврите вычитаны носителем** (плейсхолдеры помечены).

### P4. Гость, онбординг языков, карта-хаб — сложность 2, около 6–8 ч
- **Scope:** публичные маршруты; выбор L1/L2 и возраста; хаб или простая карта с 6–8 узлами; прогресс гостя в `localStorage`.
- **DoD:** от открытия сайта до первого вопроса не больше 3 тапов без логина; RTL-карта проверена.

### P5. Аудио — сложность 2 (дизайн и пайплайн), около 6–10 ч
- **Scope:** список клипов из словарей; запись или генерация; AudioButton с фолбэком и состоянием `unavailable`; громкость и «спокойный режим».
- **DoD:** у каждого задания и числа 0–20 на HE и RU есть клип; проверено на iPadOS Safari и Android Chrome, включая автоплей после первого тапа; при отсутствии клипа игра проходима.

### P6. Лендинг и case study — сложность 2, около 6–8 ч ★ «вау» для работодателя
- **Scope:** `/` для ребёнка и взрослого; `/case-study`:
  - «до/после» (контраст, тап-таргеты, бесконечный цикл → раунд);
  - идея «фигуры — это и бренд, и контент»;
  - живое переключение RU→HE и HE→RU с зеркалированием;
  - витрина токенов;
  - архитектура «игра = данные».

  Плюс короткие WebM с lazy-загрузкой.
- **DoD:** Lighthouse: Performance ≥ 90, Accessibility 100; CLS < 0.05; скриншоты в README. Копирайт по брифу владельца.

### P7. Родительская зона и профили — сложность 4, около 20+ ч (UI около 8–10 ч) ★ витрина full-stack
- **Scope:** гейт, вход взрослого, профили (ник, аватар-фигура, возрастная группа, пара языков), перенос прогресса гостя, дашборд «повторить слова», настройки (никуд, спокойный режим), удаление данных.
- **DoD:** гейт не проходится тапами наугад; у ребёнка нет персональных полей кроме ника; удаление работает и подтверждается; все экраны соответствуют AA в обоих направлениях.

### P8. Карта прогресса и альбом стикеров (полировка) — сложность 2, около 6–8 ч
- **Scope:** анимированная тропинка, персонаж, стикеры-фигуры, пустое и «всё собрано» состояния.
- **DoD:** управляется с клавиатуры; проверена в LTR и RTL; ничего не запирает.

**Порядок:** P1 → P2 → P3 → P4 → P5 → P6 → P7 → P8. После P1–P4 уже есть показываемое демо RU↔HE. P5–P6 превращают его в убедительное портфолио, а P7 закрывает full-stack. Ориентир — около 3 месяцев при 5–10 ч в неделю на P1–P7.

## 6. Источники (что открывал и что взял)

- **NN/g, «Children's UX: Usability Issues in Designing for Young People»** — возрастные сегменты 3–5 / 6–8 / 9–12, крупный текст для младших, длинный текст пропускают, звук и анимацию дети любят, несколько путей навигации путают. Отсюда возрастные плитки и один путь «Играть → карта → раунд».
