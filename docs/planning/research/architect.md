# FunZone: технический аудит и целевая архитектура (ревизия 3)

**Автор:** Distinguished Systems Engineer (совет по планированию)
**Дата:** 2026-10-06 · **Аудит выполнен на ветке** `agents-workbench` (в истории один squash-коммит `b122762`)

**Вводные владельца (накопительно):**
1. **CLIL-продукт**: ребёнок учит второй язык через математику и логику. Одна игра идёт на целевом языке или переключается между целевым и родным, с озвучкой.
2. **Языковые пары:** сначала **RU↔HE** (RTL — часть ядра), затем **RU↔EN**. Владелец живёт в Израиле, **сам озвучивает и вычитывает RU, HE и EN**.
3. Время: **5–10 ч в неделю, один человек**. Phase 1 — около 3–4 месяцев.
4. Хостинг: **AWS**, при разумной стоимости.
5. Одна ветка на задачу, PR в `main`.
6. Целевая роль владельца — **full-stack разработчик**. План должен показывать архитектуру, AWS, CI/CD, тесты и наблюдаемость.
7. **Соавтор не давал согласия на коммерческое использование**, владелец хочет «переписать своё». Phase 1 — **чистое переписывание** движка, игр и общего UI под новый контракт силами владельца, а не правка совместного кода. Стратег рекомендует **6–8 игр с контентом в данных (математика и логика)** вместо 35, особенно без английских phonics-игр из раздела Letters.

**Что изменилось в ревизии 3:**
- **новый репозиторий** с историей только от владельца (§3.2);
- таблица «что заменяется, что выбрасывается» (§3.3);
- legacy-адаптер убран: старые игры не переносятся;
- архитектура «игра = механика + контент» (§3.9, §3.10);
- RU и HE лингвистика: плюралы, род числительных, никуд (§3.7);
- озвучка голосом владельца вместо Polly (§3.7.4);
- набор из 8 игр на 6 механиках (§3.10);
- пакеты пересчитаны (§5).

> **⚠ Приоритет разделов.** §8 «Решения совета» принят позже остальных разделов и **имеет приоритет** над ними. Что именно он заменяет: СУБД MySQL → **PostgreSQL 17 на RDS в il-central-1** (§3.4, §3.6, §4.1); Drizzle с SQL-ревью миграций (§3.4); 6 механик → **4 шаблона Jony плюс 2 во второй волне** (§3.10); звёзды и подсказки по правилу Jony (§3.9); контракт игры по форме QA (§3.9); журнал происхождения `PROVENANCE.md` вместо `ASSETS.md` (§3.2); подтверждено, что у Polly **нет иврита** (§3.7.4). Пересчёт часов — в §9.

> Оговорка: в части авторских прав и лицензий я описываю инженерную практику, а не юридическую консультацию. Перед коммерческим запуском (Phase 2) владельцу стоит один раз проконсультироваться с юристом по IP в Израиле.

## 0. Коротко

1. **Аудит старого кода** (§2) нужен теперь не как список правок, а как **список требований к новому коду**: каждая находка превращается в правило, тест или DoD нового пакета. Старый код не правится, не деплоится и удаляется из продуктовой линии.
2. **Срочно, при любом сценарии:** seed (`DB/gamedatabase.sql:109`) публикует личный email владельца и bcrypt-хэш короткого пароля админа. Старый API позволяет анонимно захватить админку (`user.js:200`). **WP-00 (2 ч):** убрать ПДн и хэши, пометить старый репозиторий как legacy, не деплоить его, сменить пароль везде, где он мог повторяться.
3. **Чистое переписывание в новом репозитории.** Владелец пишет код с нуля, без копирования файлов. Старый репозиторий архивируется с благодарностью соавтору. В репозитории **нет LICENSE**, значит старый код по умолчанию — совместная собственность. Новый репозиторий с историей «только владелец, только через PR» снимает вопрос происхождения кода и одновременно служит витриной процесса для работодателя.
4. **Архитектура — «static-first, API-optional»:** движок, игры, контент и аудио — статика в S3 + CloudFront. Гость играет без бэкенда, прогресс хранится локально. API (Phase 1B) — аккаунты и синхронизация на том же домене.
5. **Игра = механика + контент.** 6 переиспользуемых механик (вопрос с вариантами, счёт объектов, пары, сортировка по корзинам, последовательность, навигация по сетке) и 8 игр поверх них. Новая игра в той же механике — это манифест, генератор и контент-пакет, без нового UI-кода.
6. **RU↔HE с первого дня:**
   - UI и игра переключают `lang` и `dir` независимо друг от друга.
   - Математика в RTL изолирована как LTR.
   - Плюралы через ICU: в иврите категории `one/two/other`, в русском `one/few/many/other` (проверено в Node).
   - **Род числительных в иврите** берётся из данных: у существительного есть поле `gender`, числительное выбирается через `select`.
   - **Никуд** — переключаемый слой текста.
   - Один шрифт на три алфавита (кандидат — Rubik: Latin, Cyrillic, Hebrew); никуд нужно проверить.
7. **Озвучка — голос владельца.** Конвейер: список фраз из контента → чек-лист записи → нормализация громкости (ffmpeg loudnorm) → MP3 с хэшем в имени → манифест. Отчёт о недостающих клипах в CI. Web Speech API — только fallback. Объём первой волны — около 150–200 клипов на язык, это 2–3 сессии записи.
8. **AWS:**
   - **1A:** S3 + CloudFront + ACM + Route 53 + Terraform + GitHub OIDC, **≈ $1.5–2 в месяц**.
   - **1B:** один EC2 `t4g.small` (API + MySQL в Docker) за тем же CloudFront по `/api/*`, SSM вместо SSH, бэкапы в S3. **≈ $18–20 в месяц**, или ≈ $5–8 при free tier.
   - RDS — по типу free tier аккаунта или в Phase 2. Fargate + ALB не нужны.
9. **График при 7.5 ч в неделю:**
   - **Phase 1A ≈ 99 ч (около 13 недель):** новый движок, UI kit, i18n и RTL, конвейер аудио, AWS, CI/CD, **3 игры RU↔HE** (Add & Subtract, Compare, Count & Say).
   - **Ещё 5 игр ≈ 32 ч** и **Phase 1B (бэкенд) ≈ 52 ч** — 4–6-й месяц.
   - Переписывание с нуля дороже, чем перенос через адаптер. Это сознательная цена за чистую IP-историю. **За 3–4 месяца реально сделать 1A и первые пакеты 1B.**

## 3. Целевая архитектура

### 3.1 Варианты Phase 1 → Phase 2

| | **A. Эволюция старого кода** | **B. Чистое переписывание, static-first на AWS (рекомендую)** | **C. Next.js full-stack** | **D. Serverless AWS** |
|---|---|---|---|---|
| IP-чистота | ✗ совместный код остаётся | ✓ новый репозиторий, только владелец | ✓ | ✓ |
| FE | CRA → Vite | Vite + React 18 + TS strict + React Router 7 | Next.js SSR | Vite |
| BE | Express 4, точечные фиксы | Express 5 + TS + zod на EC2 (1B) | route handlers | Lambda + API GW |
| БД | MySQL | MySQL 8 + Drizzle (контейнер, затем RDS) | RDS | DynamoDB / Aurora SL v2 |
| RU↔HE, RTL, аудио | сбоку | ядро | i18n-routing из коробки | как в B |
| AWS/мес | ~$15–20 | 1A ~$2, 1B ~$18–20 | дороже (Amplify/ECS) | ~$0–5 |
| Для full-stack резюме | слабо | сильно: контракты, i18n/RTL, IaC, OIDC, CI/CD, тесты, наблюдаемость | сильно, но типово | сильно, но не по силам при 5–10 ч/нед |

**Рекомендация: B.** Переписывание обязательно из-за IP. Раз так, выгоднее сразу строить «правильную» архитектуру, а не повторять старую. Static-first даёт показываемый продукт через 3 месяца независимо от готовности бэкенда.

**Чего не делаем:** SSR, микросервисы, ECS/Kubernetes, Redis, GraphQL, CMS в Phase 1 (контент — данные в git, их правит владелец через PR).

### 3.2 Репозиторий и IP-гигиена

- **Новый репозиторий** (рабочее имя — §6, вопрос 4): история с первого коммита состоит только из PR владельца. Код старого проекта не копируется, в том числе фрагментами. Если удобно, при переписывании можно смотреть на старую игру в браузере, но не в редакторе.

### 3.7 Многоязычие RU↔HE (затем EN) — слой ядра

**3.7.1 Модель локалей**
```ts
type LocaleCode = 'ru' | 'he' | 'en';
interface LocaleInfo { code: LocaleCode; dir: 'ltr' | 'rtl'; status: 'enabled' | 'beta' | 'hidden';
                       fontStack: string; hasNiqqud?: boolean; speechLang: string /* 'he-IL' */ }
interface LanguagePrefs { native: LocaleCode; target: LocaleCode;
                          mode: 'target' | 'native' | 'bilingual'; showNiqqud: boolean }
```
- Первый экран: «Я говорю на… / Я учу…» (RU→HE или HE→RU; EN позже). Выбор хранится в профиле, в URL игры есть `?learn=he`.
- `<html lang dir>` следует **родному** языку (интерфейс), а **игровая область** получает свои `lang` и `dir` по **целевому**. Русский интерфейс с ивритской игрой (LTR-рамка, RTL-контент) и наоборот — штатные сценарии, оба покрыты e2e.

**3.7.2 Тексты и лингвистика**
- **UI-строки:** `i18next` + ICU MessageFormat, namespace на модуль.
- **Контент игр** — пакеты `games/<slug>/content/<locale>.json` по zod-схеме игры. **Общие языковые ресурсы** лежат в `content/<locale>/`: числительные, цвета, фигуры, похвала.
- **Плюралы.** Русский: `{n, plural, one {# звезда} few {# звезды} many {# звёзд} other {# звезды}}` (дробные — `other`). Иврит: категории `one, two, other` (у «двух» отдельная форма, `שני כוכבים`). Обе схемы проверены через `Intl.PluralRules`.
- **Род числительных в иврите.** Существительное в контенте несёт `gender: 'm' | 'f'`, числительное выбирается через ICU `select` по роду. «שלושה כוכבים» и «שלוש בובות» — разные слова и **разные аудиоклипы**. При абстрактном счёте («сколько будет 3+4») в иврите традиционно используется женская форма: это нужно закрепить в контенте и подтвердить с педагогом. В русском род влияет только на 1 и 2 («один/одна», «два/две»).
- **Никуд.** Текстовые поля на иврите хранятся в двух вариантах: `text` и `textNiqqud`. Отображение управляется `showNiqqud` (по умолчанию включено для изучающих иврит и для младшего возраста). Fallback: если варианта с никудом нет, показывается `text`, а в `content:report` выдаётся предупреждение. Шрифт **должен корректно рисовать никуд** — это проверяется в WP-04 визуальным тестом.
- **`Intl` везде, где он работает:** `NumberFormat` (в иврите латинские цифры), `PluralRules`, `DisplayNames` (названия языков в переключателе: «иврит», «רוסית»), `ListFormat`.
- **Покрытие:** `content:report` в CI строит матрицу «игра × язык → текст, никуд, аудио». Для `enabled`-языков пропуски валят сборку. Игра видна только при полном покрытии пары языков.
- **Псевдолокали:** `en-XA` (удлинение) и `xx-RTL` (псевдо-RTL на латинице) — дешёвый способ найти ошибки вёрстки до перевода.

**3.7.3 RTL**
- Только логические CSS-свойства, stylelint `use-logical` в CI.
- **`<MathExpr>` = `<bdi dir="ltr">`**: в израильской школе `3 + 4 = 7` пишется слева направо. Числа в RTL-тексте изолируются.
- Стрелки «назад» и «вперёд» зеркалятся по `dir`. Циферблат, числовая прямая и последовательности не зеркалятся: это семантика, а не направление чтения. **Числовая прямая в иврите — открытый вопрос к педагогу**, в учебниках встречаются оба направления. Компонент поддерживает оба варианта через параметр.
- Шрифт: **Rubik** (OFL, Latin + Cyrillic + Hebrew, округлый детский характер) или Noto Sans + Noto Sans Hebrew. Self-hosted через `@fontsource` с `unicode-range`. Перед выбором проверить рендер никуда.

**3.7.4 Озвучка голосом владельца**
- **Основной источник — записи владельца** (RU, HE, EN): единый голос, естественная интонация, бесплатно, и это уже готовая «студийная» история для продукта.
- **Объём первой волны (3 игры, на язык):** числительные 0–20 (в иврите × 2 рода, ≈ 40), числительные 21–100 по необходимости уровня 3, операции и слова сравнения (≈ 10), инструкции (≈ 15), похвала и ободрение (≈ 15), существительные для счёта (≈ 30) — **≈ 120–150 клипов**. С остальными играми выходит ≈ 200. Это 2–3 сессии записи по часу.
- **Конвейер (WP-09):**
  1. `audio:todo --locale he` выгружает из контента чек-лист `key, text, textNiqqud, gender, note` (CSV) только для недостающих клипов;
  2. владелец записывает (Audacity, маркеры с именами ключей, экспорт по меткам);
  3. `audio:build`: ffmpeg trim silence → `loudnorm` (EBU R128, ≈ −16 LUFS) → MP3 64 kbps mono → имя = sha256 содержимого → `audio-manifest.<locale>.json`;
  4. **готовые MP3 хранятся в git** (≈ 15 KB на клип, ≈ 3 МБ на язык) и деплоятся вместе с сайтом; исходные WAV лежат в версионируемом приватном S3-бакете `audio-src` (бэкап, вне git);
  5. в CI `audio:check` валит сборку, если для `enabled`-языка у фразы нет клипа.
- **Склейка фраз** («три плюс четыре») — последовательное воспроизведение токен-клипов через `AudioContext` с короткими паузами. Целые предложения-инструкции записываются целиком.
- **Fallback:** Web Speech API (`he-IL`, `ru-RU`) для фраз без клипа в `beta`-языках. Субтитры показываются всегда.
- **Polly** остаётся опцией Phase 2 для EN или для быстрого черновика, если запись станет узким местом. В основной путь не входит.

**3.7.5 Режимы CLIL**
- `target`: задание и озвучка на целевом языке.
- `native`: всё на родном (разогрев).
- `bilingual`: задание на целевом, по кнопке «🔁» и автоматически после второй ошибки показывается и звучит родной вариант. `usedNativeHint` пишется в ответ.
- На экране итога — **«Новые слова»**: слова целевого языка из раунда с кнопкой прослушать. Это задел для личного словаря ребёнка в Phase 2.

### 3.8 Приватность детей

Аккаунт только у взрослого. У ребёнка нет ПДн. В детской зоне нет сторонних трекеров. Sentry без PII и replay. Шрифты и аудио — свои статические файлы, внешних запросов нет. Аналитика по собственным `game_sessions` и отчётам CloudFront.

### 3.9 Контракт: движок → механика → игра

Три уровня, каждый со своей ответственностью:

```ts
// 1) Движок (engine/): жизненный цикл, скоринг, раунды, адаптация, языки, аудио, прогресс.
// 2) Механика (mechanics/<name>/): переиспользуемый интерактив. Не знает о конкретной игре и языке.
export interface MechanicProps<Item> {
  item: Item;                                   // одно задание (данные, без текста)
  view: ItemView;                               // уже локализованные строки, ключи аудио, MathExpr
  lang: { target: LocaleInfo; native: LocaleInfo; mode: LanguageMode; showNiqqud: boolean };
  answer(choice: unknown): void;                // движок проверяет, считает, блокирует повтор
  hint(): void;                                 // запрос подсказки на родном языке
  reducedMotion: boolean;
}
// 3) Игра (games/<slug>/): манифест + генератор + контент. Почти без UI-кода.
export interface GameDefinition<Item, Content> {
  manifest: { slug: string; version: number; category: 'math' | 'logic'; mechanic: MechanicId;
              ageMin: number; ageMax: number; skills: string[]; roundLength: number; icon: string };
  contentSchema: z.ZodType<Content>;
  generate(rng: Rng, difficulty: 1 | 2 | 3, content: Content): Item;  // чистая функция
  check(item: Item, choice: unknown): boolean;                       // чистая функция
  present(item: Item, ctx: PresentCtx): ItemView;                    // ICU, род, никуд, ключи аудио
}
```
- **Игра не рендерит и не считает очки.** Скоринг, блокировка повторного ответа (F-03), таймеры с cleanup (F-17), seeded RNG (F-09), lazy loading, `aria-live` и аудио — забота движка и механики. **Все игровые правила — чистые функции**, поэтому покрытие тестами почти бесплатное.
- Регистрация: `import.meta.glob('./games/*/index.ts')` для манифестов и ленивый импорт механики. Языки игры выводятся из наличия валидных контент-пакетов.
- **Адаптация:** чистая `nextDifficulty(history)` в `shared`, межраундовая, с гистерезисом (повышение после двух хороших раундов подряд, понижение после одного плохого).
- **Расширяемость:** если игре нужен собственный интерактив, она объявляет `mechanic: 'custom'` и даёт свой компонент, реализующий `MechanicProps`. Контракт с движком при этом тот же.

### 3.10 Набор игр Phase 1: 8 игр на 6 механиках

| # | Игра (рабочее имя) | Механика | Контент в данных | Языковой фокус CLIL | Пакет |
|---|---|---|---|---|---|
| 1 | **Add & Subtract** | `choice` (вопрос + 3–4 варианта) | диапазоны по уровням, шаблоны вопроса | числительные, «плюс/минус/равно», «ועוד/פחות/שווה» | WP-11 (1A) |
| 2 | **Compare** | `choice` (больше / меньше / равно) | диапазоны, иконки | «больше/меньше», «גדול מ/קטן מ» | WP-11 (1A) |
| 3 | **Count & Say** | `count` (тап по объектам, затем ответ) | существительные с родом и картинками | **род числительных HE, плюралы RU** | WP-12 (1A) |
| 4 | **Missing Number** | `choice` | числовые ряды, шаг по уровню | порядковые и количественные числительные | G1 |
| 5 | **Word Memory** | `pairs` (картинка ↔ слово ↔ звук) | наборы слов по темам | словарь (животные, цвета, фигуры) | G2 |
| 6 | **Sort It** | `sort` (перетащить в корзины) | категории: цвет, форма, размер | названия признаков и категорий | G3 |
| 7 | **What Comes Next** | `sequence` | паттерны цветов и фигур | цвета и фигуры, «следующий», «הבא» | G4 |
| 8 | **Direction Maze** | `grid` (лабиринт по устным командам) | генератор лабиринта, набор команд | **направления в RTL-контексте**: «направо/налево», «ימינה/שמאלה» | G5 |

Почему так:
- математика и логика дают **конечный и озвучиваемый словарь**;
- 3 механики из 6 (`choice`, `count`, `pairs`) покрывают 5 игр;
- Count & Say и Direction Maze специально нагружают сложные места иврита (род и направление);
- английские phonics-игры, география и флаги не входят: у них низкая CLIL-ценность для RU↔HE и высокая цена контента.

Порядок механик: `choice` → `count` → `pairs` → `sort` (drag-and-drop с тачем и клавиатурой — самая дорогая) → `sequence` → `grid`.

### 3.11 Ленивая загрузка, PWA, доступность

- Route-level split. Механика грузится лениво, контент-пакеты — только для пары языков, аудио — только текущей игры. `size-limit`: initial JS ≤ 120 KB gzip.
- **PWA** (`vite-plugin-pwa`): опционально после 8 игр. Precache shell и аудио выбранной пары языков, `registerType: 'prompt'`, `/api` не кэшируется.
- **Доступность — DoD UI kit и механик:** видимый фокус, тач-цели ≥ 44px, `aria-live` на языке игры, субтитры к любому звуку, `prefers-reduced-motion`, управление с клавиатуры (в `sort` — альтернатива drag-and-drop), `axe` без serious/critical.

Ежедневный `mysqldump` в S3 (lifecycle 30 дней), **с проверенным восстановлением**. Логи через `awslogs` в CloudWatch. Alarm `StatusCheckFailed` → recover.
- **RDS** — сразу, если аккаунт на legacy free tier, иначе в Phase 2 с runbook переезда. **Fargate + ALB** — только при доходе.
- **Защиты от счёта:** AWS Budgets ($10, $25, $40), Cost Anomaly Detection, MFA на root, IAM Identity Center, теги `project=<имя>`. В плане **нет NAT Gateway, ALB и Multi-AZ** — это самые частые «тихие» статьи.

### 4.2 IaC

Terraform, remote state в S3 (`use_lockfile`, без DynamoDB), два собственных маленьких модуля (`static-site`, `api-host`). `plan` выполняется в PR, `apply` — вручную через `workflow_dispatch`.

### 4.3 CI/CD (GitHub Actions; для публичного репозитория бесплатно, для приватного — 2000 минут в месяц)

- **`ci.yml` (каждый PR):** `npm ci` → ESLint, stylelint (`use-logical`) и Prettier → `tsc -b` → Vitest (shared, engine, механики, генераторы) → `content:report` + `audio:check` → build → `size-limit` → Playwright (RU→HE, HE→RU, псевдо-RTL, `axe`). В 1B добавляются API-интеграционные тесты с `services: mysql:8.4`.
- **Безопасность:** Dependabot, `npm audit --omit=dev --audit-level=high` (блокирующий), CodeQL, gitleaks.
- **`deploy-web.yml` (push в main):** OIDC → build → `s3 sync` (ассеты и аудио с `immutable`, `index.html` с `no-cache`) → инвалидация `/index.html` → smoke.
- **`deploy-api.yml` (1B):** образ arm64 → ECR → `ssm send-command` запускает `deploy.sh` (pull → `db:migrate` → `up -d` → ожидание `/ready` → при провале откат на предыдущий тег) → smoke `/api/ready` через CloudFront.

### 4.4 Ветвление и PR

- Trunk-based: ветка `wp/NN-slug` на пакет, живёт ≤ 2 недель. Если пакет не помещается, его режут.
- PR в `main`, **squash-merge**, заголовок в формате Conventional Commits, шаблон PR с чек-листом DoD и разделом «как проверить», обязательный `ci.yml`, линейная история, защищённый `main`.
- `main` всегда деплоится. Незаконченное скрыто флагами: `LocaleInfo.status`, игра без полного покрытия не видна.
- Self-review по чек-листу плюс агент-ревьюер на PR, затрагивающих безопасность, деньги и инфраструктуру (WP-10, 18, 20).
- Планы совета из ветки `agents-workbench` старого репозитория переносятся в `docs/` нового репозитория первым PR (WP-01).

### 4.5 Наблюдаемость

- **Sentry** FE (1A) и BE (1B): release = SHA, source maps, без PII и без replay.
- **pino** JSON → CloudWatch Logs (14 дней).
- **Route 53 health check** или UptimeRobot на `/` и `/api/ready`.
- **Отчёты CloudFront:** популярные игры и пары языков.
- **SQL-вью продуктовых метрик** (1B): раунды, completion rate, `native_hints_used` по языкам.
- **AWS Budgets.**
- Для резюме это законченная история: «ошибки, логи, аптайм, продуктовые метрики, стоимость».

RLS принимаю как **возможность на Phase 2**, а не как задачу 1B: при одном API-пользователе и проверке владения в repository-слое это второй рубеж, который стоит часов, а не минут. **D2. Регион: `il-central-1` (Тель-Авив) для всего, что содержит или может содержать персональные данные** (RDS, EC2/API, бэкапы, CloudWatch Logs), и для origin-бакетов. *Отклонено:* `eu-central-1` и `us-east-1`.
- Причина: резидентность данных израильских семей упрощает соответствие поправке 13. Детали подтверждает юрист.
- Ограничения:
  1. `il-central-1` — **opt-in регион**, его надо включить в аккаунте;
  2. сертификат ACM для CloudFront выпускается в `us-east-1` при любом регионе;
  3. CloudFront глобален и работает с S3-origin в `il-central-1` штатно;
  4. Polly в регионе не нужен: иврита у Polly нет вовсе (D10).
- Цены в `il-central-1` обычно на ~10–25% выше `us-east-1`. **В этом аудите я их не проверял.** Первая задача WP-10:
  `aws ec2 describe-instance-type-offerings --region il-central-1 --filters Name=instance-type,Values=t4g.micro,t4g.small`

**D4. Учебный контент: источник истины — файлы в git, БД — проекция с 1B.** *Отклонено:* БД как источник с первого дня (Joe), JSON-пакеты навсегда (моя rev 3).
